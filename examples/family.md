# Before-and-after proof examples

Each row links to a runnable example, its assumptions, and its verification transcript. Counts refer to the named workload and cost unit in that row. The log, Merkle, and migration examples also replay the decision against an operating-system file, SHA-256, or SQLite.

| Repository | Engineering decision | Before → after | What proves the result |
|---|---|---|---|
| [software-optimality](https://github.com/clpi/software-optimality/tree/69eb8e11c6dd36f934095810bc663528a3e15c12/examples) | CI release scheduling | 23 → 16 ticks | A feasible two-runner schedule reaches the 16-tick critical-path lower bound. |
| [software-doesnt-have-to-regress](https://github.com/clpi/software-doesnt-have-to-regress/tree/c36829da6f687d52b7d7998edc5ef55f4c244077/examples) | Ordered log writes | 4,096 → 64 writes | Every legal batching preserves order and fits at most 64 records per write. The replay checks all 16,384 output bytes. |
| [software-is-incrementally-certifiable](https://github.com/clpi/software-is-incrementally-certifiable/tree/c9ffd49a906038d29d3e0d726093c410b3db798e/examples) | Merkle recertification | 2,047 → 11 hashes | One fresh receipt is required at each changed path level. All 1,024 possible single-leaf edits matched a clean rebuild. |
| [software-doesnt-need-review](https://github.com/clpi/software-doesnt-need-review/tree/40b1e885658951fa3fd17f42f5017fed5765f22b/examples) | SQLite migration review | 6 → 2 owner decisions | Four reports determine the policy verdict. Each of the other two is compatible with opposite decisions. |
| [software-testing-is-redundant](https://github.com/clpi/software-testing-is-redundant/tree/66f65b6f44ac0249d11451cac089283aa1756240/examples) | Quota policy | 256 → 2 load probes | Downward closure propagates the two boundary answers to all loads. Omitting either boundary admits a wrong neighboring threshold. |
| [software-benchmarking-is-redundant-and-suboptimal](https://github.com/clpi/software-benchmarking-is-redundant-and-suboptimal/tree/4314a181bc3d1fb35972031273c796aca10d15f5/examples) | Sharded benchmark | 8 → 1 runs | Seven receipts remain valid. Two possible values for the changed shard force a fresh result. |
| [software-fuzzing-is-suboptimal](https://github.com/clpi/software-fuzzing-is-suboptimal/tree/18d9569b581a3d2900b0613b33fc00e4b464ffa5/examples) | Valid frame coverage | 256 → 16 decoder calls | All 16 valid commands have a unique encoding. Each call can cover at most one command. |
| [software-is-composable](https://github.com/clpi/software-is-composable/tree/69bac7241582e4a2a9438052db82b5b21d0033a1/examples) | Checkout rebuild partition | 5 → 3 services | Every closed partition keeps checkout, invoice, and tax together. Splitting the block can hide a broken export. |
| [software-is-incrementally-safe](https://github.com/clpi/software-is-incrementally-safe/tree/8ad1dd2624c41023919ab7c41a285de15b3ce673/examples) | Changed qualification policy | 4 → 2 fresh evaluations | Exactly two cached verdicts must flip. The incremental result equals a clean evaluation for arbitrary rule lists. |
| [software-is-quantifiable](https://github.com/clpi/software-is-quantifiable/tree/f370992611d8c722e4897e67dbb8eaecf3d872ed/examples) | Execution ledger repair | 2 missing → 0, with 2 new records | The holes name distinct execution IDs. A single appended record cannot cover both. |
| [software-is-solvable](https://github.com/clpi/software-is-solvable/tree/5bbceee7e4270d838115dbfc8fb218ebee641638/examples) | Restore qualification | 8 → 6 work units | The joint run covers both missing premises and is cheapest among all subsets of the declared menu. |
| [software-frontier-is-solvable](https://github.com/clpi/software-frontier-is-solvable/tree/6a41c7be3c1b01492f96b75cbf0a28b11ab9faff/examples) | Replica placement under outage | 4 → 3 frontier layouts | All eight masks are covered. With the hub offline, deleting old winners misses both one-replica fallbacks. |
| [software-compilers-lose-info](https://github.com/clpi/software-compilers-lose-info/tree/f531e31a4e647461a28228e4b9d64f40d1782908/examples) | Origin of a folded quote | 1 indistinguishable price → 4 recoverable origins | Two fixed-width metadata bits suffice. No one-bit scheme recovers both choices. |
| [software-is-more-traceable-than-you-think](https://github.com/clpi/software-is-more-traceable-than-you-think/tree/4420fb1e5422d965668c66f93d9d352cc3cec982/examples) | Invoice approval provenance | 8 events → 2 or 3 premises | The recorded route determines the necessary set. An untagged approval admits both explanations. |
| [software-is-a-closed-loop](README.md) | Batch tuning and requalification | 8 → 2 calls | Each transition enforces the cap. Every feasible starting pin reaches an eligible minimum within three proposals. |

From the root of any linked repository, run `sh examples/check.sh` with its indicated Lean version. The three execution replays also use Python 3. Each transcript records a passing proof run and a rejected mutation.
